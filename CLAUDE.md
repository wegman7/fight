# Fight — project guide

2.5D platform fighter (Smash-like mechanics, original content). Rust workspace + Godot 4.7.

- `sim/` (`fight_sim`): all gameplay rules, deterministic, engine-free. See `sim/CLAUDE.md`.
- `balance/` (`fight_balance`): balance-testing harness. CPUs fight every matchup
  headlessly on the sim and the results become a win-rate matrix and buff/nerf
  suggestions (never written to the source). See `balance/CLAUDE.md` and `balance/README.md`.
- `gdext/` (`fight_gd`): godot-rust extension that feeds input to the sim and renders it,
  plus the Melee-style menus (stocks → character select → stage select). See `gdext/CLAUDE.md`.
- `godot/`: Godot project. `main.tscn` root node is `FightWorld` (defined in Rust); it
  also holds the beach backdrop (purely decorative; sand and ocean shaders in `godot/shaders/`,
  next to the hit sparks' `hit_spark.gdshader`, the pug's `fur.gdshader`, the soldier's `camo.gdshader`, `gear.gdshader` and
  `weapon.gdshader` (which share `soldier.gdshaderinc`), and the chef's `chef_*.gdshader`).
- `godot/music/`: the two background tracks — `rising_motif.mp3` during matches,
  `untitled.mp3` in the menus — loaded and looped by `gdext/src/music.rs`.
- `art/fighter/`: Blender source for the chef model (`godot/models/fighter.glb`) and his
  pie projectile (`godot/models/pie.glb`), generated by a Python script. His skin, cloth,
  hair and leather are Godot shaders (`chef_*.gdshader`) swapped in by `fighter.glb.import`
  and `pie.glb.import`; they read rest-pose positions and baked AO from the mesh. See `art/fighter/README.md` before touching animations.
- `art/pug/`: the black pug model (`godot/models/pug.glb`), also script-generated, on a
  four-legged rig. Its fur shader is swapped in by `pug.glb.import`. See `art/pug/README.md`.
- `art/samurai/`: the samurai model (`godot/models/samurai.glb`), script-generated on the
  chef's skeleton plus a katana bone, reusing the chef script's helpers. Laced lamellar
  armor and a kabuto over kimono and hakama; his lamellar, cloth, skin, blade and iron
  textures are seeded images generated by the script (extracted on import as
  `godot/models/samurai_*.png`). See `art/samurai/README.md`.
- `art/ninja/`: the ninja model (`godot/models/ninja.glb`), script-generated on the chef's
  skeleton, with generated tiling normal/albedo textures (cloth, skin, hair, steel,
  leather) embedded in the .glb. See `art/ninja/README.md`.
- `art/soldier/`: the soldier model (`godot/models/soldier.glb`) and his grenade
  (`godot/models/grenade.glb`), script-generated on the chef's skeleton plus a rifle
  bone. A masked operator: helmet, goggles, ear-pro, a plate carrier with MOLLE and
  pouches, pads, holster, knife and a scoped carbine. His camo, gear and weapon shaders
  are swapped in by `soldier.glb.import` and read a baked rest position (UVs) and
  ambient occlusion (vertex color). See `art/soldier/README.md`.
- `art/hobo/`: the drunk hobo model (`godot/models/hobo.glb`), script-generated on the
  chef's skeleton plus a bottle and a shopping-cart bone. A bearded drifter in a knit
  beanie, a tattered, patched overcoat, fingerless gloves and worn-out shoes, his cloth,
  skin and hair textured by seeded, script-baked albedo/roughness/normal PNGs. See
  `art/hobo/README.md`.
- `art/beach/`: script-generated backdrop props (palms, rock, sailboat). See `art/beach/README.md`.
- `art/stage/`: the stage's platform models (`stage.glb`, `raft.glb`), script-generated,
  textured by `wood.gdshader` and `stone.gdshader` swapped in on import. See `art/stage/README.md`.
- Characters (`Character` in `sim/src/character.rs`) each have their own tuning and
  moveset in the sim; `look()` in `gdext/src/lib.rs` picks each one's model. Stages are
  `StageId` (`sim/src/stage.rs`); CPU difficulty is `CpuLevel::level(1..=9)` (`sim/src/cpu.rs`).

## Commands

```sh
cargo test                                         # sim, harness and menu logic tests: run after any change to any of them
cargo clippy --workspace --all-targets             # keep at zero warnings
cargo build                                        # required before running Godot
cargo run --release -p fight_balance -- --games 200            # balance: CPU-vs-CPU win-rate matrix (~10 s)
cargo run --release -p fight_balance -- --games 100 --tune 4   # balance: buff/nerf loop, prints a suggested diff
cargo run --release -p fight_balance -- --set ninja:damage=+3,weight=+3 --seed 100 --games 200   # try a change
godot --headless --path godot --quit-after 600     # smoke test (menus, model checks): must print no ERROR lines
FIGHT_DEMO=1 godot --headless --path godot --quit-after 900   # smoke test a match (skips the menus)
FIGHT_DEMO=1 godot --path godot                    # visual check: CPUs fight, hitboxes on
FIGHT_CPU=3 godot --path godot                     # skip the menus: P1 vs a level-3 CPU (levels 1-9)
FIGHT_STAGE=sandbar FIGHT_DEMO=1 godot --path godot   # pick the stage for FIGHT_DEMO / FIGHT_CPU
FIGHT_CHARACTERS=samurai,pug FIGHT_DEMO=1 godot --path godot   # pick P1's and P2's characters for either
FIGHT_MUSIC_VOLUME=50 godot --path godot    # music volume 0-100 (default 70); in-game: - lowers, = raises
godot --path godot --write-movie <dir>/f.png --fixed-fps 60 --quit-after 120   # render frames to PNG for inspection
blender --background --factory-startup --python art/fighter/build_fighter.py   # rebuild chef .blend + .glb, and pie.glb
blender --background --factory-startup --python art/pug/build_pug.py           # rebuild pug .blend + .glb
blender --background --factory-startup --python art/samurai/build_samurai.py   # rebuild samurai .blend + .glb
blender --background --factory-startup --python art/ninja/build_ninja.py       # rebuild ninja .blend + .glb, and its textures
blender --background --factory-startup --python art/soldier/build_soldier.py   # rebuild soldier .blend + .glb, and grenade.glb
blender --background --factory-startup --python art/hobo/build_hobo.py         # rebuild hobo .blend + .glb
blender --background --factory-startup --python art/beach/build_beach.py       # rebuild backdrop props
blender --background --factory-startup --python art/stage/build_stage.py       # rebuild stage platforms
godot --headless --path godot --import             # after a .glb changes
```

If `cargo` isn't on PATH, prefix with `. "$HOME/.cargo/env";`.

## Architecture rules

- **Gameplay goes in `sim/`, never in `gdext/`.** If it affects who wins (movement,
  hits, damage, timers), it's in the sim and has a test. `gdext` only builds `Input`s
  and draws state.
- **The sim is deterministic.** No floats, no `HashMap` iteration, no time or
  OS randomness inside `sim/` (a seeded PRNG stored in the struct, like `Cpu`'s, is fine).
  `World` must stay `Clone + PartialEq` (rollback snapshots).
- **CPU players live in `sim/src/cpu.rs`** and only produce `Input`s; they never
  change fighter state directly. `gdext` just calls `Cpu::think` for CPU slots.
- **Menus only choose a `MatchSetup`** (stocks, stage, each port's character and
  CPU level). Their state and layout are in `gdext/src/menu.rs`, which has no Godot
  nodes and is unit tested there; `gdext/src/menu_view.rs` only draws it.
- **Models are visual only.** Animations are named after `Fighter::anim()` and
  seeked to the sim frame each render frame. They never free-run or drive gameplay.
  A model needs an animation for each of `STATE_ANIMS`, its character's
  `Character::moves()` names and the dodge names. gdext logs an `ERROR` at startup for
  any that are missing, so the smoke test catches them. A new move needs a new action
  in that character's `art/*/build_*.py`.
- **Balance changes are measured, then applied by hand.** Run the harness before and
  after a tuning change and quote its numbers (with error bars) in the commit. It
  measures characters as the CPU plays them: read the AI flags and the caveat in
  `balance/README.md` before acting on a result, and fix CPU bugs rather than tuning
  around them. Whole-character knobs are `FighterParams::damage_scale` /
  `knockback_scale` (percent, 100 = as written in `moves.rs`).
- Frame data uses Smash conventions: 1-based frames, angles in degrees (0 = forward,
  90 = up), knockback with Melee/Brawl formula constants.

## Docs

**Keep the docs current as part of every change, not as a follow-up.** The docs are
`CLAUDE.md` and `README.md` at the root and in each crate (`sim/`, `gdext/`, `balance/`). Before
calling a task done, check each one the change touches: commands, env vars, controls,
file/module tables, test locations, "where things live", "not built yet", and rules.
Fix anything stale, and delete statements that are no longer true. If a new directory,
crate or subsystem needs its own explanation, add a `README.md` (for people) and/or a
`CLAUDE.md` (rules for agents) there and link it from the root docs.

## Known quirks

- `godot --headless --import` sometimes segfaults on exit inside Godot itself
  (no frames in our library). Rerun it. Game runs aren't affected.
- `--write-movie` only records frames while the window is actually drawn. If frames
  freeze or the "frames at 60 FPS" count is short, the window was occluded: add
  `--always-on-top`.
- If Godot says `Cannot get class 'FightWorld'`, the extension isn't registered:
  check `godot/.godot/extension_list.cfg` contains `res://fight.gdextension`
  (re-import to regenerate), and that `cargo build` produced the dylib.
- After music plays, a headless run prints `1 resources still in use at exit` plus two
  leaked audio instances: Godot's headless (Dummy) audio driver doesn't release an active
  `AudioStreamPlayer`'s playback on shutdown. Benign and headless-only — windowed runs
  stop and free it normally. The music code still calls `stop()` on `exit_tree`.
